## Why freshness parsing changed

Old `sector_from_ring` could select old complete status/rows when a later failed read and a new dump nonce remained in the same circular buffer. Existing-row completeness plus a later producer/dump echo did not establish that the rows belonged to that execution. `test_old_complete_rows_new_read_failure_new_nonce_never_becomes_second_read` explicitly demonstrates the old validator returning the prior sector after synthetic `flash read fail` or `malloc fail`; strict parser rejects both. These are injected parser counterexamples, not observed live read failures or proof that earlier successful observations were false.

New [`nor_freshness.py`](../../src/rcominote/experiments/nor_freshness.py) linearizes one complete4096-byte circle ending at the **unique current dump echo**, checks its exact newline-terminated command length, and selects the **most recent producer of any target**. It requires the nearest preceding target-matching status, exactly32 contiguous canonical fixed-width rows, and exact observed FW010004 prefix/delimiter bytes through producer→current dump. It rejects failure/error text, extra status/producer, wrong offsets/lengths, duplicate or truncated markers, and row gaps/format changes. It never searches backward for a more convenient old candidate or fills missing bytes from an oracle.

For a second read, the first operation's unique dump nonce is mandatory and must fully precede the second status within that same circle. The anchored interval must contain exactly one current status/producer and no failure/error. Thus a second file cannot simply reuse the first ring, omit its declared prior marker or ignore a hidden intervening failed read. Tests cover circular wrap, changed current bytes, conflicting independent sectors, missing/duplicate prior markers, wrong target/oracle claims and failed final-audit promotion.

Freshness establishes a bounded text association only. Successful pairing additionally requires both actual producer/download barriers, complete Actions/Boyi/HCI/identity audits, ordered distinct executions/new files and equal independently produced sectors. The unknown target has no independent byte oracle; allFF is an observed candidate value, not a success shortcut.
