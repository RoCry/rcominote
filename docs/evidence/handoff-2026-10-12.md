## The device

Seeyon **CoMi Note** — a desk/notepad-style AI voice recorder with a screen,
~58 GiB storage, BLE. One owned unit, serial `C261CF0430`, firmware `1.0.4`.
Earlier packaging sample: model `SY-N2A3F-5H2`, CMIIT ID `26J11X2GE501`, 64 GB,
BT 5.3, ~400 mAh. It is **BLE-only for data**; the USB cable is charge-only
(the SiFli RT-Thread CDC shell seen on `/dev/cu.usbmodem1201` is a *different*
device — a Hiveton e-reader, repo `~/w/_hw/rcwodle` — do not confuse them).

## Chipset / SoC — current best conclusion (thread 1)

**Vendor = Actions Technology (炬芯). Strong evidence, no teardown yet.**
Basis (all passive, reproducible):

- Live GATT enumeration of the unit shows, besides the Boyi service `e5e0`:
  - `e49a3001-f69a-11e8-8eb2-f2801f1b9fd1` (rx `…3002` write, tx `…3003`
    notify) — **byte-for-byte the Actions Zephyr SDK's BLE log service**
    (`~/w/_tmp/lv_port_actions_technology/action_technology_sdk/application/bt_watch/src/bt_log/log_service.c`).
  - `0000f5f0` (`…f5f1` write, `…f5f2` notify) — an Actions bt_watch-style
    sppble stream.
- The wearable SoC deep-read already placed the OTA service in this same
  `…-f69a-11e8-…` family (ATS308x / ZS308x):
  `~/w/_hw/rlcdv/docs/research/wearable-hardware/08-actions-sdk-deep-read.md`.
- Grey-market Actions SDKs for private study live in
  `~/w/_tmp/actions-sdk-research/` (per the wearable-hardware memory; owner
  authorized download for pre-contract study, kept out of the repo). Public
  mirror: `~/w/_tmp/lv_port_actions_technology/`.

**Still open / next steps for the chipset:**
- **Teardown for the silkscreen** — the exact model (ATS3085S? ZS308B? another
  308x) is unconfirmed without reading the main IC part number. This is the
  single highest-value action.

## Custom firmware — write + flash (thread 2, not started)

Nothing attempted yet. Known facts that bound the approach:

- **An unauthenticated debug door exists.** The `e49a3001` BLE log service runs
  arbitrary shell commands: in the SDK source `_logsrv_proc_console_text` →
  `shell_execute_cmd`, TLV type `0x01`, no auth. **This session deliberately did
  NOT send to it** (not needed for the host/sync work, and a safety classifier
  flagged a probe). A firmware team may want to evaluate it as a controlled
  bring-up/diagnostics entry on the owned unit — understand its risk first and
  treat it as device-bricking-capable.
- **OTA exists in the Boyi app protocol on the Mova branch, not seen on Boyi**
  — re-check the 1.1.2 JS (`index-Btih_BUR.js`, Mova section) and the hardened
  1.2.4 build (see below) for a Boyi OTA/firmware command. The device's own
  `/firmware/update.json`-style flow is unknown for CoMi.
- **The Actions SDK OTA transport is documented** (TLV: REQUEST_UPGRADE /
  CONNECT_NEGOTIATION / REQUIRE_IMAGE_DATA / SEND_IMAGE_DATA(_WITH_CRC) /
  VALIDATE; GATT `e49a25f8-f69a-11e8-…`, rx `…25e0`, tx `…28e1`; SPP 650 B /
  BLE 230 B unit; LZMA + hpatch diff; **no signature by default**) — see
  `08-actions-sdk-deep-read.md` lines ~227-232. **Check whether CoMi exposes
  the `…25f8` OTA service** (it was not in this unit's enumerated service list —
  re-enumerate, it may appear only in a DFU/OTA mode).
- To build/flash you will likely need: the exact SoC part, the Actions
  toolchain (Zephyr-2.7.0 fork; public Beta SDK referenced in the wearable
  docs), and the flash/recovery entry (USB? the charge-only cable suggests no
  USB CDC in normal mode — look for a test-point UART or a BLE/USB DFU mode).

## Official app capability notes (context, already gathered)

- Store build is **1.2.4 (versionCode 10)**, installed via Heytap market
  (sideloading 1.1.2 failed with ColorOS `-99`; store install worked).
- 1.2.4 is **hardened with 爱加密 (ijiami)** — `ijiami.ajm/.dat`,
  `libijmDataEncryption*.so`; DEX is encrypted, so static protocol diffing of
  the new build needs dynamic instrumentation (Frida/root) — likely not worth
  it; the 1.1.2 JS is the clean protocol source.
- 1.2.4 asset inventory reveals the app's cloud/AI feature set: Alibaba **NUI**
  speech SDK (`nui.json`, `WakeUp.bin`) + Baidu grammar + TTS (ASR / wake /
  TTS); document edge-detection models (`detect.ms`/`corner.ms`/`angle.ms`,
  OCR scan); H5 note rendering via mermaid / echarts / markdown-it / wangeditor
  / highlight.js (AI summaries, mind maps, charts).
- Live app testing beyond the login screen (`AccountLoginActivity`) needs the
  owner's CoMi account — **the owner has taken over live app testing**; the
  next team does not need to.
