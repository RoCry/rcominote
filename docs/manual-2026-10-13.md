来源：[IMG_6808，结构图](evidence/manual-2026-10-13/IMG_6808.jpg)：
显示屏、电源键、录音键、两个分别标为“麦克风孔”的位置、四触点磁吸充电口。
两个孔不能证明两颗模拟麦，也不能确定骨传导拾音器的位置。

既有单声道MP3和`ADC_0`绑定不能推翻双拾音设计。

## 按键、录音状态与NOTE/CALL

来源：[IMG_6808，操作说明](evidence/manual-2026-10-13/IMG_6808.jpg)、
[IMG_6809，暂停/结束及模式](evidence/manual-2026-10-13/IMG_6809.jpg)。

| 用户操作 | 文档行为 |
|---|---|
| 长按电源键3秒 | 正常开机/关机；没有强制复位描述 |
| 待机灭屏时短按电源键 | 点亮屏幕 |
| 向上推动录音键 | 开始录音，振动一次 |
| 录音中短按电源键 | 暂停录音；该段未独立说明暂停后的再次短按行为 |
| 向下推动录音键 | 结束并保存，振动两次，显示`SAVE!` |
| 亮屏、未录音时双击按键 | NOTE/CALL互切；配图指向电源键 |
| 亮屏、录音中双击按键 | 切换模式后重新开始录音；不是无副作用查询 |
| NOTE | 普通会议、访谈、需求沟通录音 |
| CALL | 将设备贴在手机上，用骨传导麦收音，专门录制通话 |

CALL文案描述接触收音，不足以推断HFP接收手机通话音频。
官方App的[23个请求表](remaining-client-contracts.md)没有已确认的NOTE/CALL设置命令；
CLI能读模式、控制录音，不因此自动具备远程切换拾音器能力。
未来若验证模式，应从idle切换，分别采集短样本并恢复原模式；
先核对状态/响应的模式值，再检查固件选路，不在录音中盲目双击。

## “录音加密”的现有反证边界

[既有CALL实时流与同名导出文件](realtime-live.md)逐字节相同，可直接解码MP3；
本轮对[删除验收留下的10256B测试录音](file-deletion.md)重新离线运行`ffprobe`、
`ffmpeg -v error -i FILE -f null -`：MP3、16000Hz、mono、32000bit/s，完整解码退出0。
未访问设备、未运行解密步骤。音频留本地，不随文档发布。

因此至少这些BLE导出样本无需客户端另行解密；不能据此否定存储层、
BLE安全层、其他录音模式或服务端加密，也不能把录音加密与NOR固件转换混为一谈。
下一步应对照录音写文件/导出读文件之间是否存在转换，避免先设计一个不必要的解密器。

## 恢复与平台资料：没有解锁的部分

三张照片未出现reset孔、强制复位、按键下载模式、固件升级或恢复步骤。
正常长按3秒依赖当前工作模式，不能作为ROM卡住后的独立退出保证。
四触点不能自行赋予VBUS/GND/D+/D−定义；仍需接线或枚举证据。
因此[ROM入口的退出条件](actual-rom-exit-condition.md)、完整NOR备份与恢复边界不变。

IMG_6809还确认CoMi App需配置企业专属服务地址，蓝牙添加示例名为`CoMi Note 2F01`；
这是说明书示例，不能替代本机广播身份。文字提到下载二维码，本次三图未见可读取二维码。
2026-10-13精确公开搜索`"SY-N2A3F-5H2"`只返回两个已有第三方认证索引
（[编号页](https://cmiitid.cn/2026-6996)、[型号核准码页](https://cmiitid.cn/26J11X2GE501)）；
`"CoMi Note" "骨传导"`无结果。未获得新原厂BSP/固件包；停止扩展同类泛搜。

## 对自写固件的直接影响

- 将模拟拾音、骨传导拾音、NOTE/CALL选路列为板级适配项；不能用单ADC实例名省略其中一路。
- 区分电源按键与录音滑键，保留按键去抖、暂停/保存、模式切换及振动反馈语义。
- 保留充电、电池监测与低功耗策略；标称续航不是参考SDK默认配置能够保证的结果。
- 优先确认匹配BSP、双拾音选路和可恢复入口；本说明书没有补齐烧录所需条件。
